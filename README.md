# تک‌نبولا — سایت اصلی فروشگاه

این پروژه‌ی Next.js (App Router) بر اساس ساختار بک‌اند و پنل ادمینی که قبلاً باهم ساختیم طراحی شده. پنل ادمین دست‌نخورده مونده؛ این یه پروژه‌ی کاملاً جدا و موازیه که به همون بک‌اند وصل میشه.

## راه‌اندازی

```bash
npm install
cp .env.local.example .env.local   # مقادیرش رو با آدرس واقعی بک‌اندت تنظیم کن
npm run dev
```

## ساختار پوشه‌ها

```
src/app/            صفحات (App Router) — هر پوشه یه route
src/components/     کامپوننت‌های قابل استفاده مجدد، به تفکیک layout / product / blog / cart / common
src/contexts/        CartContext (سبد خرید، localStorage) و AuthContext (لاگین OTP)
src/lib/             api.js (کلاینت API)، seo.js، format.js، categories.js
backend-additions/   فایل‌های *پیشنهادی* بک‌اند (پایین‌تر توضیح داده شده)
```

هر فایل داخل پروژه کامنت‌گذاری شده — مخصوصاً جاهایی که یه فرض یا تصمیم طراحی گرفتم، با ⚠️ مشخص شده تا دفعه‌ی بعد که فایل رو بهم بدی راحت‌تر دوباره context بگیرم.

## نکته‌ی خیلی مهم: چیزهایی که باید با بک‌اند واقعی چک/هماهنگ بشه

بک‌اند رو تغییر ندادم و کدهای فعلی routes/models رو کامل در اختیار نداشتم، برای همین این فرانت با چند تا **فرض** ساخته شده. قبل از تست کامل، این‌ها رو با بک‌اند واقعی مقایسه کن:

| فرض | کجا استفاده شده | اگه فرق داشت چیکار کنم |
|---|---|---|
| `GET /api/products` فیلترهای category, brand, minPrice, maxPrice, minRating, inStock, isNew, isBestseller, search, sort, page, limit رو ساپورت می‌کنه | صفحه‌ی محصولات و دسته‌بندی | پیاده‌سازی پیشنهادی توی `backend-additions/productRoutes-additions.mjs` هست |
| `GET /api/products/facets` برندهای موجود + بازه‌ی قیمت رو برمی‌گردونه | فیلتر سایدبار | همون فایل بالا، endpoint جدید |
| `Order.user` رفرنس به `User._id` داره | چک‌اوت، سفارش‌های من، صفحه‌ی کاربران پنل ادمین | همون فرضی که قبلاً هم برای صفحه‌ی کاربران گذاشتیم |
| `POST /api/orders` سفارش می‌سازه با ساختار `{items, shippingInfo, shippingMethod, couponCode}` | چک‌اوت | پیشنهادی توی `backend-additions/orderRoutes-additions.mjs` |
| `GET /api/orders/my` و `GET /api/orders/my/:id` | سفارش‌های من | عمداً مسیر `/my` رو انتخاب کردم تا با `GET /orders/:id` ادمین تداخل نکنه |
| `POST /api/products/:id/reviews` برای ثبت نظر توسط مشتری | بخش نظرات صفحه‌ی محصول | پیشنهادی توی `backend-additions/productRoutes-additions.mjs` |
| میدلور `requireAuth` (کاربر لاگین‌کرده‌ی عادی، نه لزوماً ادمین) وجود داره | همه‌ی روت‌های پیشنهادی سمت مشتری | اگه نداری، شبیه `requireAdmin` بساز ولی فقط چک کنه توکن معتبره (بدون چک نقش ادمین) |

## ورود (SMS.ir) — وضعیت فعلی: کار می‌کنه، بدون تغییر لازم برای بعداً

صفحه‌ی `/login` فقط از `sendOTP` / `verifyOTP` / `getMe` که از قبل توی بک‌اند و پنل ادمین وجود داره استفاده می‌کنه. یعنی:
- الان: هر رفتار تستی فعلی OTP توی بک‌اندت (مثلاً چاپ کد توی کنسول) همینجوری از این صفحه هم کار می‌کنه.
- وقتی SMS.ir رو وصل کردی: **هیچ تغییری توی فرانت لازم نیست.** فقط داخل روت `/auth/send-otp` بک‌اند، به‌جای هر مکانیزم فعلی، واقعاً به SMS.ir وصل میشه.

## پرداخت (زرین‌پال) — وضعیت فعلی: حالت سندباکس (تستی ولی واقعی)

`backend-additions/paymentRoutes.mjs` رو باید به بک‌اند اضافه کنی (روت جدیده، چیزی جایگزین نمیشه). این فایل:
- الان با merchant_id تستی رسمی زرین‌پال (`00000000-...`) و آدرس `sandbox.zarinpal.com` کار می‌کنه — یعنی می‌تونی کل مسیر خرید رو از اول تا آخر امتحان کنی، فقط پول واقعی رد و بدل نمیشه.
- وقتی merchant_id واقعی گرفتی: فقط `ZARINPAL_MERCHANT_ID` رو توی `.env` بک‌اند ست کن. کد خودش می‌فهمه و میره سراغ `payment.zarinpal.com` (production). **کد دیگه نیازی به تغییر نداره.**
- قبل از رفتن به production، حتماً یه بار endpoint های `pg/v4/payment/*` رو با مستندات فعلی zarinpal.com/docs چک کن (تاریخ نوشتن این کد: مرداد ۱۴۰۵).

مدل `Order` باید سه فیلد اختیاری `paymentStatus`, `paymentAuthority`, `paymentRefId` رو داشته باشه — جزئیاتش ته فایل `paymentRoutes.mjs` هست.

## دسته‌بندی‌ها

چون `Product.category` توی بک‌اند یه رشته‌ی آزاده (نه مدل جدا)، تمام درخت دسته‌بندی‌ها (برای مگامنو، فوتر، فیلتر، صفحات `/category/*`) توی یه فایل واحد تعریف شده: `src/lib/categories.js`. موقع ثبت محصول جدید توی پنل ادمین، مقدار فیلد «دسته‌بندی» باید دقیقاً یکی از `slug` های همون فایل باشه (مثلاً `gpu`, `laptop`, `gaming-chair`) تا محصول درست زیر دسته‌ش نمایش داده بشه.

## سئو

- هر صفحه (محصول، دسته، مقاله) `generateMetadata` مخصوص خودش رو داره: عنوان، توضیحات، canonical، Open Graph.
- صفحه‌ی محصول و مقاله، JSON-LD (schema.org Product / Article / BreadcrumbList) دارن.
- `/sitemap.xml` و `/robots.txt` خودکار از روی `src/app/sitemap.js` و `robots.js` ساخته میشن.
- لینک محصولات (`/products/[id]-[slug-فارسی-یا-انگلیسی]`) خوانا و سئوفرندلیه، بدون اینکه لازم باشه فیلد slug به مدل Product اضافه بشه (توضیح کامل توی `src/lib/seo.js`).

## چیزهایی که عمداً ساده نگه داشته شدن (برای دور بعد، در صورت نیاز)

- مدیریت آدرس‌های ذخیره‌شده‌ی کاربر (فعلاً فقط توی خودِ فرم چک‌اوت وارد میشه)
- کد تخفیف واقعاً اعمال نمیشه (فیلدش هست، منطق محاسبه‌ش placeholder صفره — باید توی `orderRoutes-additions.mjs` تکمیل بشه)
- ویشلیست
- سرچ با پیشنهاد خودکار (autocomplete)
